0311 个潜在问题

按"严重程度 + 改起来便宜"排序。前 3 个是真 bug, 后 8 个是设计 smell。

BUG · P0
Scheduler 反复 missed, cache 永不过期
现象: 22:00 后大面 105 还停在 18:27 warmup 时算的 8/10 截面, 8/11 盘中数据没人触发重算
证据: /tmp/server.log 18:30 起 20+ 条 missed by 0:01-5min
修复: core/scheduler.py:94 misfire_grace_time=60 太小, 提到 600s; 或 scheduler.executors.default pool size 加大
BUG · P0
KPI 卡 vs industry tab 数据源不同源
KPI 卡 (1586↑/3483↓/139平): 走 market_breadth 表 (xtquant_breadth.fetch 写)
industry tab 大面/大肉: 走 industry_stats in-process cache (qmt_monitors 算)
风险: 一个 stale, 另一个新鲜, 用户对不上
BUG · P1
Staleness 时间戳误导
summary.data_date=2026-08-10 (CSV 截面) + realtime_data_date=2026-08-11
顶部 "T+1 数据 2026-08-10 · 实时 2026-08-11" 显示 OK, 但**大面/涨跌实际是 8/11 实时** vs **主力是 8/10 截面** — 一行字"涨跌/大肉来自 QMT tick, 实时" 容易被忽略
SMELL · P2
大面数包含跌停数 (重复)
is_big_loss = change_pct ≤ -5, 跌停 (≤-10) 一定满足
例: 银行 -10% → 算大面 + 跌停 (各 1)
看电力设备 8 大面 1 跌停, 大面数实际是 "非跌停但 ≤-5%" + "跌停" 的和 → 概念不清
可选: 大面分两层: big_loss_ex_dt = 跌穿未跌停
SMELL · P2
MA10 实时 vs CSV 算法不一致
ma10_csv: close 10 天算术平均
ma10_realtime: 前 9 天 close + today tick ÷ 10 (顶替最后一天)
两个均值定义不同, 行业 ma10_realtime 跟个股 ma10_realtime 不严格可比
SMELL · P2
大面列没颜色 / 视觉权重低
现有列: ma10_ratio 红色, 差值 pp delta, 涨停数/跌停数纯数字
大面数: 跟"涨停数/跌停数" 同等样式纯数字, 但 28 (有色金属) 跟 0 (银行) 视觉差异不够强
建议: 极值加 mini-bar / 文字色 (≥10 红 / ≥3 橙 / 0 灰)
SMELL · P2
Cache miss 时同步重算阻塞 HTTP
_get_qmt_industry_stats_payload 缓存未命中 → 同步调用 build_qmt_industry_stats_payload (5208 只 ~1min)
这一刻 HTTP 会卡 60s, 前端白屏, 浏览器超时
建议: cache miss 时直接返回 stale + 异步刷新
SMELL · P2
Sort 切换时大面 / 主力 sort 行为不一致
toggleStatsSort 默认 desc 数值, asc 字符串。点"大面数"列, 应该按大面降序
但点"主力·T+1"列按 today_main_inflow 降序 — OK
点"个股数"按 stock_count 降序 — OK
一致性没问题, 但**没有 secondary sort** (大面 0 的行业按 sector 字母)
SMELL · P3
QMT 断连 → 整个 industry tab 消失
_get_qmt_industry_stats_payload L615: if not enabled or not connected: return _empty_qmt_industry_stats_payload()
现象: QMT bridge 临时不通, 整页 31 行业消失, 显示"暂无行业统计数据" — 用户以为服务挂了
建议: 返回 stale cache + 顶部 warning banner
SMELL · P3
CSV 缺 2 只票 (sz301655 / sz301717)
quant.loader 日志 18:27:50 警告: 这 2 个 code CSV 不存在
5208 - 2 = 5206 只进 cache
微小偏差, 但 industry_stats_count=31 是从 groupby 后算的, 不会显式说"少 2 只"
SMELL · P3
首页 KPI 大面数缺失
QmtDataPage 顶部 5 个 KPI 卡: 跌停/上涨/下跌/平盘/成交额
**没大面/大肉** (需要后端改 market_breadth 表 schema)
user 上一轮明确说"不要加在 KPI 卡" — 标记为 deferred
